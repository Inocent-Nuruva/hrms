# Activities and Performance: targeted audit and refactoring plan

The implementation below is applied to the repositories. Existing endpoint paths, authorization guards, domain enums, and working query flows are retained. All 136 HTTP route declarations in the six audited controllers were compared with the pre-refactor files and are unchanged.

## Lifecycle blueprint

Activities: configure categories/policies → create draft work → complete checklist and required outcomes/evidence → review the daily summary → submit → manager approves, returns, or rejects. Only draft/returned reports remain editable, as enforced by the existing backend lifecycle. Checklists have no weight field in this domain; their size, IDs, and contents are validated instead of inventing weighted checklist behavior.

Performance: configure year/period and evaluation catalogs → create a 100% KPI set/plan → submit self review → submit manager review → complete configured approval steps → HR approval/publication. Mid-cycle employee responses and final KPI finalization remain separate existing workflows. Reopening is explicit, retains the existing configuration switch, and respects the configured cycle workflow.

## Execution sequence

1. Separate loading, permission failures, missing configuration, legitimate empty data, and editable draft state.
2. Validate form details with named Zod contracts, then review and confirm; retain inputs and show backend errors inline.
3. Guard async reads and mutations by request generation, view/input scope, token, and credential version, with cleanup on unmount or changes.
4. Enforce exact persisted weights, calendar boundaries, metric bounds, evidence ownership, and lifecycle prerequisites at the backend.
5. Serialize review transitions, workflow approvals, and default switches; include related audit writes in the transaction.
6. Translate database conflicts at the scoped controller boundary and verify the existing contracts and concurrency behavior.
